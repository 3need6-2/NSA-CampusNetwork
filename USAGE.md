# Usage Guide

## Quick Start

```bash
python app.py
# Open http://localhost:5001
```

## Home Page

The home page displays:
- System status indicators
- Current data statistics (users, packets, traffic, IPs)
- CSV file upload form
- Navigation to dashboard and real-time screen

### Upload Traffic Data

1. Click the upload area or drag-and-drop a CSV file
2. File must contain the required columns
3. After upload, the system analyzes the data and redirects to the dashboard

### CSV Format

```
timestamp,src_ip,dst_ip,src_port,dst_port,protocol,bytes,app_category,user
2025-12-01 08:00:15,192.168.1.100,8.8.8.8,52341,53,UDP,256,DNS,student_001
```

Required columns: `timestamp`, `src_ip`, `dst_ip`, `src_port`, `dst_port`, `protocol`, `bytes`, `app_category`, `user`

## Security Dashboard

Access: Click "Enter Security Dashboard" or navigate to `/dashboard`

### Sections

**Attack Source Tracking**
- Number of unique source IPs
- Most targeted port/service
- Blocked entities count

**Traffic Statistics Cards**
- Total traffic (bytes, MB, GB)
- Total packets
- Active users
- Unique IPs

**Hourly Traffic Trend**
- Line chart showing traffic volume over 24 hours
- Hover for exact values

**Application Category Distribution**
- Doughnut chart of traffic by app type
- DNS, Social Media, Video Streaming, CDN, P2P, etc.

**User Traffic Ranking**
- Bar chart of top users by traffic volume

**AI Security Audit**
- Risk level indicator (low/medium/high/critical)
- List of detected threats with severity
- Suggested mitigation actions
- Rate limiting/step-up auth/quarantine recommendations

**ML Anomaly Detection**
- Table of anomalous users with scores
- Key evidence for each anomaly
- Refresh button to re-run detection

**User Profiles**
- Cards showing user tags
- Click to expand: app distribution, protocol ratio, active hours charts

### DeepSeek Review

Click "Run DeepSeek Review" button (requires configured `DEEPSEEK_API_KEY`):
- Sends summarized risk evidence to DeepSeek API
- Receives secondary analysis and validation
- Results appear in the AI Security section

## Real-Time Dashboard

Access: Click "Real-Time Dashboard" or navigate to `/realtime`

### Controls

- **Start Replay**: Begin replaying CSV data at specified rate
- **Stop Replay**: Stop the replay engine
- **Rate Slider**: Adjust replay speed (events per second)

### Displays

- **KPI Cards**: Events sent, cumulative traffic, active users, source IPs, active alerts
- **Real-Time Traffic Curve**: 5-second bucket traffic volume rolling chart
- **Event Stream**: Last 30 replayed traffic events with timestamps
- **Alert Stream**: Real-time alerts generated by replay engine rules:
  - Port scan detection (6+ ports in 30 seconds)
  - Large traffic burst (>= 50,000 bytes per record)
  - Sensitive port access (21, 22, 23, 25, 53, 135, 139, 445, 3306, 3389, 6379)

### API Usage

```bash
# Start replay at 10 events/sec, loop enabled
curl -X POST http://localhost:5001/api/realtime/start \
  -H "Content-Type: application/json" \
  -d '{"rate": 10, "loop": true}'

# Check status
curl http://localhost:5001/api/realtime/status

# Adjust rate to 20
curl -X POST http://localhost:5001/api/realtime/rate \
  -H "Content-Type: application/json" \
  -d '{"rate": 20}'

# Stop replay
curl -X POST http://localhost:5001/api/realtime/stop
```

## Using the API

All endpoints return JSON. See `docs/api.md` for full documentation.

### Get Traffic Statistics

```bash
curl http://localhost:5001/api/stats
```

### Get Dashboard Data

```bash
curl http://localhost:5001/api/dashboard_data
```

### Get User Profiles

```bash
curl http://localhost:5001/api/user_profiles
```

### Search

```bash
# Search by user, IP, or app category
curl "http://localhost:5001/api/search?q=student_001"
```

### Export Data

```bash
# Export all analysis data as JSON
curl http://localhost:5001/api/export/json

# Export traffic data as CSV
curl http://localhost:5001/api/export/csv
```

## Configuration

Edit `config.yaml` or set environment variables (see `.env.example`):

| Variable | Description |
|---|---|
| `FLASK_SECRET_KEY` | Session signing key |
| `FLASK_HOST` | Bind address |
| `FLASK_PORT` | Listen port |
| `FLASK_DEBUG` | Enable debug mode |
| `DEEPSEEK_API_KEY` | DeepSeek API key (optional) |

## Best Practices

1. **Data preparation**: Clean CSV data before upload (remove duplicates, validate timestamps)
2. **Regular monitoring**: Check the dashboard daily for new anomalies
3. **ML tuning**: Adjust `contamination` parameter in `utils/ml_anomaly.py` based on your environment
4. **Security**: Always use HTTPS in production, never expose debug endpoints publicly
5. **Backup**: Regularly backup the `data/` directory
